- **v1.0.0 — one scoring path, two endpoints.** The single-score endpoint body was extracted into `_score_one_submission(submission_id)` (raises HTTPException with specific statuses: 404 unknown/unparsed, 503 Supabase-or-Groq, 500 persistent malformed LLM output); `POST /api/submissions/score-pending` loops it sequentially and catches HTTPException per item, so batch and single can never diverge in behavior.
- **v1.0.0 — pending means "no complete score set".** Batch eligibility = lacking all four criteria (the same completeness rule as the ranking engine), so partial/interrupted runs self-heal by re-scoring; complete sets are never re-scored (append-only score history preserved, no wasted Groq quota).
- **v1.0.0 — the frontend talks to the backend ONLY through `frontend/lib/api.ts`.** Typed response models mirror the routes; every error becomes `ApiError(status, humanMessage)` (429 → rate-limit explainer; network down → plain-English message; otherwise the backend's own `detail` passes through). Pages never call fetch directly — keeps the PRE-DEPLOY-CHECKLIST "no leaked internals" rule enforceable in one place.
- **v1.0.0 — jsdom cannot render next/link**: any Vitest suite rendering a component that imports NavLinks must `vi.mock` it to a null component (applied in page.test.tsx, dashboard/page.test.tsx, SubmissionDetailView.test.tsx).

- **v0.7.0 — feedback is ONE CURRENT row per submission (upsert), while scores stay append-only history.** Feedback is derived data reflecting the latest scores; regeneration overwrites via `upsert(on_conflict="submission_id")`. Migration 0007 stores strengths/weaknesses as jsonb arrays, suggestion as text, verdict with a CHECK constraint.
- **v0.7.0 — shortlist context comes from the SAME engine, never recomputed ad hoc.** `load_leaderboard(hackathon_id, top_n, min_score)` was extracted from the v0.6.0 rankings route and is the single path to composite/rank/shortlisted for feedback generation, CSV export, and PDF export. POST feedback takes `top_n` (default 5) mirroring GET /api/rankings so tone matches whatever cutoff the organizer demos with.
- **v0.7.0 — FeedbackAgent reuses scoring idioms but stays an independent module:** module-level `_get_async_groq_client` + `_sleep` seams (tests patch them exactly like `agents.scoring.base`), MAX_RETRIES=3 with corrective re-prompt on JSONDecodeError/ValueError/TypeError, rate-limit/connection backoff inside `_call_groq`, bool-guard on suggestion (Python bool-is-int trap), `normalize_unicode_dashes` applied to every stored string, AGENT_VERSION derived from APP_VERSION.
- **v0.7.0 — export filenames are sanitized defensively:** user-controlled hackathon_id / team_name are reduced to `[A-Za-z0-9_-]` runs collapsed into single underscores (fallback stems `default` / submission_id) before landing in Content-Disposition — blocks header injection; verified by parametrized tests incl. `../../etc/passwd`.
- **v0.7.0 — PDF renderer escapes everything it renders:** justifications/bullets are LLM or user content; `xml.sax.saxutils.escape` wraps all Paragraph text, empty feedback lists render safely, missing feedback prints a "not generated yet" note instead of failing the export.
- **v0.6.0 — composites are computed ON THE FLY, never persisted.** The leaderboard always reflects current rubric weights + freshly scored submissions, zero denormalization drift. Ranking logic is pure (`agents/ranking/engine.py`); backend fetches and delegates. Deterministic tie-break chain: composite DESC → innovation DESC → submission_id ASC; composites rounded to 4dp BEFORE tie grouping so ties are bit-identical floats. Cutoffs (`top_n` | `min_score`, inclusive) are mutually exclusive — 422 if both. Unscored/partial never appear in `ranked` but are counted. Rubric fallback is VISIBLE (`rubric_source: "fallback"` + equal weights), never silent.
- **v0.6.0 rubric config:** migration 0006 adds `rubric_config(hackathon_id, criterion, weight)` seeded with equal 25% rows for 'default'; weights accept fractions (~1.0) or percentages (~100) normalized in `validate_weights`. Submissions are NOT hackathon-scoped yet — single-hackathon reality; full table scoping deferred to v3.x per roadmap.
- **v0.5.0 — scoring is an async parallel fan-out.** `scorer.score_submission` gathers the four specialists over ONE shared `AsyncGroq` client (`asyncio.gather`, `return_exceptions=True`) and raises the FIRST failure — fail-closed so v0.6.0 composites always have all four criteria, never partial rows. No staggering: 4 concurrent calls << Groq's ~30 RPM. The route awaits the coroutine; test fakes over `backend.routes.scoring.score_submission` must be `async def`. Backoff goes through a module-level `_sleep` indirection so tests patch the seam, not global asyncio. Retry policy unchanged: RateLimitError/APIConnectionError only.
- **v0.5.0 — no DB migration for the agent split.** `scores.criterion` already carries agent identity 1:1, so agent_name would be redundant; provenance stays in `agent_version` (now `v0.5.0`/`v0.6.0`). **Keep the four specialist agents as narrow independent modules** (`base.py` + one file per agent) per the project rule — don't collapse them back into a single prompt.
- **Boolean guard in LLM JSON parsing:** Python `bool` is an `int` subclass — `True` would otherwise pass range checks as score 1. `SpecialistAgent.parse_score` rejects `bool` with `TypeError` before the int-range validation (still retryable).
