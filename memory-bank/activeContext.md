## Recent decisions
- **v0.7.0 — feedback is ONE CURRENT row per submission (upsert), while scores stay append-only history.** Feedback is derived data reflecting the latest scores; regeneration overwrites via `upsert(on_conflict="submission_id")`. Migration 0007 stores strengths/weaknesses as jsonb arrays, suggestion as text, verdict with a CHECK constraint.
- **v0.7.0 — shortlist context comes from the SAME engine, never recomputed ad hoc.** `load_leaderboard(hackathon_id, top_n, min_score)` was extracted from the v0.6.0 rankings route and is the single path to composite/rank/shortlisted for feedback generation, CSV export, and PDF export. POST feedback takes `top_n` (default 5) mirroring GET /api/rankings so tone matches whatever cutoff the organizer demos with.
- **v0.7.0 — FeedbackAgent reuses scoring idioms but stays an independent module:** module-level `_get_async_groq_client` + `_sleep` seams (tests patch them exactly like `agents.scoring.base`), MAX_RETRIES=3 with corrective re-prompt on JSONDecodeError/ValueError/TypeError, rate-limit/connection backoff inside `_call_groq`, bool-guard on suggestion (Python bool-is-int trap), `normalize_unicode_dashes` applied to every stored string, AGENT_VERSION derived from APP_VERSION.
- **v0.7.0 — export filenames are sanitized defensively:** user-controlled hackathon_id / team_name are reduced to `[A-Za-z0-9_-]` runs collapsed into single underscores (fallback stems `default` / submission_id) before landing in Content-Disposition — blocks header injection; verified by parametrized tests incl. `../../etc/passwd`.
- **v0.7.0 — PDF renderer escapes everything it renders:** justifications/bullets are LLM or user content; `xml.sax.saxutils.escape` wraps all Paragraph text, empty feedback lists render safely, missing feedback prints a "not generated yet" note instead of failing the export.
- **v0.6.0 — composites are computed ON THE FLY, never persisted.** The leaderboard always reflects current rubric weights + freshly scored submissions, zero denormalization drift. Ranking logic is pure (`agents/ranking/engine.py`); backend fetches and delegates. Deterministic tie-break chain: composite DESC → innovation DESC → submission_id ASC; composites rounded to 4dp BEFORE tie grouping so ties are bit-identical floats. Cutoffs (`top_n` | `min_score`, inclusive) are mutually exclusive — 422 if both. Unscored/partial never appear in `ranked` but are counted. Rubric fallback is VISIBLE (`rubric_source: "fallback"` + equal weights), never silent.
- **v0.6.0 rubric config:** migration 0006 adds `rubric_config(hackathon_id, criterion, weight)` seeded with equal 25% rows for 'default'; weights accept fractions (~1.0) or percentages (~100) normalized in `validate_weights`. Submissions are NOT hackathon-scoped yet — single-hackathon reality; full table scoping deferred to v3.x per roadmap.
- **v0.5.0 — scoring is an async parallel fan-out.** `scorer.score_submission` gathers the four specialists over ONE shared `AsyncGroq` client (`asyncio.gather`, `return_exceptions=True`) and raises the FIRST failure — fail-closed so v0.6.0 composites always have all four criteria, never partial rows. No staggering: 4 concurrent calls << Groq's ~30 RPM. The route awaits the coroutine; test fakes over `backend.routes.scoring.score_submission` must be `async def`. Backoff goes through a module-level `_sleep` indirection so tests patch the seam, not global asyncio. Retry policy unchanged: RateLimitError/APIConnectionError only.
- **v0.5.0 — no DB migration for the agent split.** `scores.criterion` already carries agent identity 1:1, so agent_name would be redundant; provenance stays in `agent_version` (now `v0.5.0`/`v0.6.0`). **Keep the four specialist agents as narrow independent modules** (`base.py` + one file per agent) per the project rule — don't collapse them back into a single prompt.
- **Boolean guard in LLM JSON parsing:** Python `bool` is an `int` subclass — `True` would otherwise pass range checks as score 1. `SpecialistAgent.parse_score` rejects `bool` with `TypeError` before the int-range validation (still retryable).
- **Stable facade in `agents/scoring/scorer.py`:** the module now orchestrates but also re-exports `CriterionScore`, `ScoringResult`, `AGENT_VERSION`, `RUBRIC`, `CRITERIA_NAMES`, `build_scoring_text` so existing backend imports/tests survive the split unchanged.
- **v0.3.6 classification routing policy:** decorative-labeled images are NEVER vision-described (any confidence); genuine diagrams misread as decoration are rescued inside `classify_image` — if the best diagram-label probability ≥ `IMAGE_DIAGRAM_FLOOR` (env, default 0.30, calibrated on live scango probes) the returned label becomes that diagram label. Rescue lives in classify.py (it owns the probs).
- **QuickGELU is forced for `pretrained='openai'`** (`force_quick_gelu=True`) — OpenAI CLIP weights need it; loading without silently degrades embeddings (open_clip's mismatch warning was appearing on every server start).
- **v0.3.6 provider selection lives in the agents layer.** `pipeline._resolve_default_describer()` reads `VISION_PROVIDER` directly (mirroring how describe.py reads GROQ_* vars); `backend/config.py` mirrors the three new env vars for parity. Explicit `describe_fn` injection always wins; unknown provider values fail fast with a ValueError listing valid options.
- **Gemini describer mirrors the Groq contract exactly:** same SYSTEM_PROMPT, `_image_mime` detection, defensive think-block strip, dash normalization, empty→ValueError (non-retryable), retry+backoff ONLY on HTTP 429 / httpx.TransportError, then raises `VisionRateLimitError`.
- **VisionRateLimitError subclasses groq.RateLimitError** so pipeline's existing `except RateLimitError` breaker trips for Gemini without touching pipeline logic. Gotcha discovered: groq's APIStatusError.__init__ reads `response.request`, so passing response=None crashes — it builds a synthetic httpx.Response(429) internally instead.
- **Default GEMINI model is `gemini-3.6-flash`** (stable, free-tier; live-verified 200 on 2026-08-24 after `gemini-2.5-flash` began returning 404 "no longer available to new users" on fresh keys — Google retires models per-key-cohort while catalogs still list them). Overridable via `GEMINI_VISION_MODEL`; newer models are an env change, not code. Non-retryable Gemini HTTP errors log the JSON error body before propagating.
- Chose FastAPI + Supabase (Postgres + Storage) for v0.1.0, matching the established tech-stack. No local SQLite fallback — real Supabase keys will be added.

Methods: GET/POST/OPTIONS; headers: Content-Type; credentials allowed. This resolved the "Network error — could not reach the backend" issue in the upload portal.
- **v0.3.0 scoring agent:** Single Groq-powered agent with hardcoded 4-criteria rubric (problem_fit, technical_depth, feasibility, innovation), JSON response format enforcement, retry/backoff for rate limits (429) and malformed JSON recovery. `POST /api/submissions/{id}/score` endpoint fetches parsed text, scores, and stores results in `scores` table. `GROQ_API_KEY` added to `.env.example` and `backend/config.py`. Committed on `feature/v0.3.0-scoring-agent` (commit `51e7fef`).

- **Unicode dash normalization:** PDF/PPTX generators emit typographic dash variants (U+2010-U+2014, U+2212) that extractors pass through verbatim and the LLM echoes into justifications. Added `normalize_unicode_dashes()` in the parsing agent (applied to all extracted text) and to LLM justifications in the scoring agent (commit `d5172bf`).
- **v0.3.5 vision provider is `qwen/qwen3.6-27b`:** live spike (`scripts/check_groq_vision.py`) showed llama-4-scout 404s on this free account and groq/compound rejects multimodal content parts; qwen3.6 accepted base64 PNG input and read text in the image correctly. Its responses include reasoning blocks that `describe.py` strips before storing. Gemini fallback deliberately NOT built speculatively (ADR-0002).
- **Image pipeline is DB-free via dependency injection:** `process_submission_images()` takes `cache_get`/`cache_put` callables so agents never import Supabase; the backend injects the service functions. Cache lookup = exact phash match then near-match scan (hamming <= PHASH_HAMMING_THRESHOLD=8), centralized in `backend/services/supabase.py`.
- **Graceful degradation rule for image understanding:** per-image failures never abort a run — classification failure skips the image; description failure stores `description: null` + `needs_human_review: true` and is NOT cached (retryable); whole-pipeline failure at the route logs a warning and stores empty descriptions. Valid uploads can never be blocked by image stages.
- **pHash fixture lesson:** flat-color/simple images alias together in pHash space (left-half vs top-half differ by only ~4 bits); test fixtures must use structurally distinct shapes (verified empirically via `scripts/check_phash_distances.py`).
